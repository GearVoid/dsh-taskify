# V0.3 STEP 1 — Host Authority

## Scope

STEP 1 migrates Taskify domain-state ownership without expanding the v0.2
constraint lifecycle.

> **STEP 1 does NOT implement Persistent Anchors.**

It does not add durable Inbox messages, raw-event recovery, resume/fork
hydration, persistent runtime context, watchState, Goal integration, or a
mechanical guard.

## Before

Taskify previously had two independent process-local facts:

- Host `activeAnchors: Map<sessionId, ...>` controlled one-shot pre-step
  injection.
- Client `TaskifySession` independently stored the final anchors and decided
  when its local anchor lifecycle ended.

There was no Host read API, revision, compare-and-swap boundary, or reliable
way for a reconnecting Client to converge with Host state.

## After

The Host now owns a `TaskifyStateProjection`, keyed only by exact `sessionId`.
It exposes complete revisioned snapshots through the existing Typert Remote:

- `getState({ sessionId }) -> TaskifyStateSnapshot`
- `compile({ ..., expectedRevision }) -> CompileResult`
- `invalidate({ sessionId, expectedRevision }) -> InvalidateResult`

Successful mutations return the complete authoritative snapshot. Failed
revision checks return `revision-conflict` plus the current snapshot. The
Client then calls `getState`; it never silently retries the mutation.

The browser `sessions` Map remains, but each entry is now request/UI
orchestration plus a disposable `hostState` snapshot cache. Removing the
Client cache does not clear Host domain state.

## State Ownership

The formal dependency-free state module is `src/shared/state.js`. Its snapshot
contains:

- `schemaVersion: 1`
- exact `sessionId`
- Host-assigned monotonic `revision`
- `durability.status`
- `goalIntegration.available: false`
- `phase: idle | pending | armed`
- pending compile binding or active Anchor snapshot
- exact `{ kind: "session", sessionId }` scope

`active.boundDraft` preserves the raw composer draft used by the UI, while
`active.sourceDraft` preserves slash-body matching and Anchor provenance. The
Host extraction code remains the only producer of Anchor values. No model-
generated domain id was added.

The current projection uses a process-local Map. In STEP 1 that Map is the
authoritative runtime source of truth, not a durability claim. A reserved
`rebuild(sessionId, snapshot)` boundary rejects revision rollback so STEP 2 can
replace the cache population mechanism without replacing the Remote schema.

## Revision and CAS

Revision rules are:

1. initial state is revision `0`;
2. only Host transitions allocate the next revision;
3. every successful mutation increments exactly once;
4. compile moves `idle/armed -> pending -> armed`, normally consuming two
   revisions;
5. compile failure clears its matching pending state and consumes a second
   revision;
6. invalidate and successful pre-step consumption each increment once;
7. a stale expected revision changes nothing;
8. rebuild refuses revision rollback.

Compile checks CAS before starting the LLM. A stale request therefore does not
spend model work. Compile completion also checks the pending revision so an
external mutation cannot be overwritten by a late model result.

## Current Durability Status

STEP 1 does not write a durable Taskify representation and does not call
`ctx.sessions.flush()`. Every snapshot therefore truthfully reports:

```text
durability.status = "unavailable"
```

`confirmed` and `failed` remain valid schema values for the later durability
write path, but STEP 1 never manufactures either value. Process restart loses
the Host projection.

## One-Shot Semantics Intentionally Preserved

The user-visible lifecycle remains:

```text
compile
-> Host arms the current draft
-> first exact matching human pre-step
-> append one plugin-sourced constraint message
-> Host transitions armed -> idle
-> later pre-steps do not inject it again
```

Draft changes still invoke an explicit Host invalidate mutation. A successful
empty extraction is represented as an armed snapshot with zero anchors so the
Client can render the authoritative no-op result; it produces no constraint
message.

No continuous `systemPrompt.context` contribution was added. No Anchor remains
active after successful one-shot consumption.

## Client Convergence

Client initialization hydrates with `getState`. Compile and invalidate use the
cached Host revision as `expectedRevision` and adopt only the snapshot returned
by Host. On conflict, Client calls `getState` and presents the converged state
without retrying the rejected mutation.

The Client may still own local-only details:

- loading/extracting state;
- `AbortController`;
- notices and Toast lifecycle;
- draft revision and request generation;
- the disposable Remote snapshot cache.

It does not create a revision, construct an authoritative Anchor result, or
clear Host state merely because a component/cache is destroyed.

## Deferred to STEP 2

STEP 2 must implement, and STEP 1 intentionally does not implement:

- Taskify-sourced identified pending `UserMessage`;
- concrete `agent.inject()` / Inbox integration;
- Inbox remove/replace for durable pending work;
- `ctx.sessions.flush()` checkpoint mapping;
- raw `session.events` plus Inbox deterministic projection recovery;
- process restart, resume, fork, and compaction-safe rebuild;
- durability status changes from actual backend outcomes.

The Remote snapshot and Host transition interfaces are designed to survive
that replacement of the process-local projection source.

## Known Integration Gaps

- The real DSH Web Agent Loop is not installed locally, so concrete
  `agent.inject()` remains unverified and unused by STEP 1.
- There is no local persistence provider; cross-process recovery is absent.
- Pre-step waterfall behavior is locally contract-tested, but the complete Web
  request path still needs integration coverage.
- There is no watchState or push transport. Host changes caused by pre-step are
  observed by Client on its next hydrate, not pushed live.
- Native Goal remains unavailable; `goal/change` vocabulary is not interpreted.
- No mutation veto, file baseline, semantic audit, or mechanical guard exists.

## Explicit Non-Expansion

There is no persistent chip lifecycle, pause/resume, per-Anchor removal, Goal
scope, path scope, Minimal Diff Mode, semantic diff audit, write-time
enforcement, automatic rollback, or systemPrompt-based continuous injection.
